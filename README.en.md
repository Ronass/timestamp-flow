# Timestamp Flow

A minimal cross-platform desktop clock: a large 24-hour clock, today's date, built-in web search, and live Unix timestamps (seconds / milliseconds). Built with [Neutralinojs](https://neutralino.js.org/) — the Windows package is only about 2.5 MB.

Current version: `1.1.0`

[简体中文](README.md) · English

## Features

- **Clock**: ticks every second, with a 12 / 24-hour toggle (12-hour mode shows AM/PM).
- **Date**: localized date and weekday (`2026年10月22日 · 星期四` / `Oct 22, 2026 · Thursday`).
- **Time zones**: switch between common IANA zones or follow the system; the panel is searchable and every entry shows its live local time.
- **Unix timestamps**: seconds and milliseconds shown side by side in the footer; click either to copy it.
- **Web search**: Google / Bing / Baidu selector, submitted to your default browser on Enter.
- **Theme**: follows `prefers-color-scheme` by default, with a manual light/dark toggle.
- **Window**: frameless, transparent, rounded corners, draggable title bar; supports always-on-top, fullscreen, minimize and close.
- **Languages**: Chinese / English, switched live without a reload.
- **Persistence**: every preference is stored in `localStorage` and restored on restart.

## Tech stack

| Layer | Implementation |
| --- | --- |
| Native shell | Neutralinojs 6.10 (official binaries in `bin/`, one per platform) |
| Rendering | System WebView (WebView2 / Edge Chromium on Windows) |
| UI | Plain HTML + CSS + JavaScript — **no bundler, no framework, no build step** |
| Native APIs | `Neutralino.window` / `os` / `clipboard` / `app`, gated by `nativeAllowList` |
| Icon generation | `scripts/make-icon.js`, hand-rolled PNG encoding in pure Node, no dependencies |
| Tests | Node's built-in `node:test`, no test framework to install |

Frontend scripts use a UMD-style wrapper (`resources/js/*.js`): they attach to `globalThis` in the browser and fall back to `module.exports` under Node, so the business logic can be `require`d directly by unit tests.

## Getting started

Requirements:

- Node.js 18 or newer
- Windows 10+ / macOS 11+ / a mainstream Linux desktop (with a WebView runtime)
- No Rust, Python or C++ toolchain needed

```bash
npm install        # installs the neu CLI
npx neu update     # first time only: downloads the native binaries into bin/
npm run dev        # start in dev mode, reading resources/ from disk
```

Dev mode loads the `resources/` directory directly, so HTML/CSS/JS edits only need a reload — no rebuild.

## npm scripts

| Command | Description |
| --- | --- |
| `npm run dev` / `npm start` | `neu run`, start in dev mode |
| `npm run build` | `neu build`, produces `dist/timestamp-flow/` (exe + `resources.neu`) |
| `npm run dist` | one-shot release: version check → icon generation → build → stage into `dist/release/` → zip → print SHA256 |
| `npm run icon` | regenerate `resources/icons/appIcon.png` |
| `npm test` | run all unit tests |

## Build and release

```bash
npm run dist
```

Output:

```
dist/release/
├── TimestampFlow-1.1.0-win-x64/
│   ├── timestamp-flow-win_x64.exe     # ~2.40 MB
│   └── resources.neu                  # ~0.10 MB
└── TimestampFlow-1.1.0-win-x64.zip    # ~1.20 MB
```

`scripts/package.js` does the following:

1. Checks that `package.json` and `neutralino.config.json` declare the same `version`; fails otherwise.
2. Verifies `resources/js/neutralino.js` exists, telling you to run `npx neu update` if not.
3. Generates the icon via `make-icon.js` if it is missing.
4. Runs `neu build` and picks the binary and resource bundle for the current platform/arch from `dist/timestamp-flow/`.
5. Copies them into `dist/release/TimestampFlow-<version>-<platform>-<arch>/`, removing a stale directory of the same name.
6. Zips the folder under the same name (`Compress-Archive` on Windows, `zip` elsewhere) and prints the zip's SHA256.

> **Packaging note**: `timestamp-flow-win_x64.exe` and `resources.neu` must stay in the same directory — one without the other will not run. On startup the executable resolves `resources.neu` relative to its own path and loads `neutralino.config.json` plus all page assets from it.

### About `resources.neu`

`neu build` packs `documentRoot` (here `/resources/`) together with `neutralino.config.json` into a single file. It is not a zip: the format is a short header followed by a JSON manifest and the raw bytes of every file concatenated in order. The manifest records `size`, `offset` and SHA256 block digests for each entry.

Consequences:

- After changing anything under `resources/` — including the version or window size in `neutralino.config.json` — you **must rebuild**. The bundle is a snapshot and never syncs automatically.
- Replace the exe and `resources.neu` as a pair; mixing versions leads to unexpected behaviour.
- Neutralino does **not** officially support embedding the bundle into the executable for single-file distribution. If you need a true single exe, consider something like Tauri instead.

## Configuration

Notable fields in `neutralino.config.json`:

| Field | Current value / meaning |
| --- | --- |
| `applicationId` | `dev.timestampflow.clock`, determines the WebView data directory |
| `documentRoot` | `/resources/`, the frontend root |
| `modes.window` | 460×334, min 360×300, centered, transparent, frameless, resizable |
| `nativeAllowList` | `app.*`, `window.*`, `os.open`, `clipboard.writeText`, `debug.log` |
| `tokenSecurity` | `one-time`, native API tokens are single-use |
| `enableInspector` | `false`, no devtools in release builds |

When you add a native capability, you must also add the corresponding API to `nativeAllowList` — otherwise the call is rejected.

## Data storage

Preferences are stored in the WebView's `localStorage` under a `tf.` prefix:

| Key | Value |
| --- | --- |
| `tf.hour12` | `'true'` / `'false'` |
| `tf.theme` | `'dark'` / `'light'` |
| `tf.pinned` | `'true'` / `'false'` |
| `tf.engine` | `'google'` / `'bing'` / `'baidu'` |
| `tf.lang` | `'zh'` / `'en'` |
| `tf.tz` | an IANA zone name, or `'local'` to follow the system |

This data lives in the WebView2 user data directory — on Windows that is `%APPDATA%\timestamp-flow\EBWebView`. Deleting the whole `%APPDATA%\timestamp-flow` directory resets everything (including caches).

## Customization

- **Add a search engine**: add `key: 'https://…?q='` to `ENGINES` in `resources/js/search.js`, then add a matching `<option>` to `<select id="engine">` in `index.html`. Engines outside the allow-list fall back to Google, which prevents arbitrary URL injection.
- **Adjust the time zone list**: edit `COMMON_ZONES` in `resources/js/zones.js` and add the Chinese names in `ZONE_NAMES` (`tests/zones.test.js` verifies that both stay in sync).
- **Add a UI language**: add a language pack to `I18N` in `resources/js/i18n.js` with exactly the same keys as `zh` (`tests/i18n.test.js` enforces key parity), then expose it in the language toggle in `renderer.js`.
- **Replace the icon**: edit `scripts/make-icon.js`, run `npm run icon`, then rebuild.

## Tests

```bash
npm test
```

13 assertions covering three blocks of pure logic: zh/en string key parity (including date formats and weekday order), the search engine allow-list and URL encoding (including unknown-engine fallback and empty queries), and time zone conversion with name fallback. The UI and native calls are not covered by automated tests and rely on manual verification via `npm run dev`.

## Known limitations

- **Depends on the system WebView**: Windows needs the WebView2 runtime (bundled with Windows 11 and the vast majority of Windows 10 installs); very old bare systems need it installed separately.
- **Not a single-file distribution**: the exe and `resources.neu` must ship together, as described above.
- **Per-platform builds**: `neu build` only produces artifacts for the host platform, so cross-platform releases require building on each target OS.
- **Transparency on Linux**: behaviour depends on the window manager and compositor and may differ from Windows; the same applies to always-on-top and fullscreen.
